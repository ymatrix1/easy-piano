# Song import spike

Checked: 2026-10-16. Bean: piano-sctg. Decision: [D11](../DECISIONS.md). Code: `tools/spikes/song-import/` (Vite page, `npm install && npm run dev`, open http://localhost:5174 in Chrome).

## Question

Can the browser split a song into stems and transcribe the piano part fast enough for a "My songs" import (D11)?

## Setup

- Chrome on Windows 11, WebGPU available, page cross-origin isolated (COOP `same-origin`, COEP `credentialless`).
- Transcription: `@spotify/basic-pitch` 1.0.1 (Apache-2.0, TF.js), thresholds onset 0.5 / frame 0.3 / min length 5 frames.
- Separation: `demucs-web` 1.0.2 (MIT) on `onnxruntime-web` 1.30.0 (MIT), model `htdemucs_embedded.onnx` (4 stems: vocals, drums, bass, other).
- Test audio: synthetic, generated by `make_test_audio.py`: own rendering of Ode to Joy (PD), 30 notes, 20.2 s, additive "piano" tone with overtones; `mix.wav` adds sine bass and noise drums. Scoring: note F1, same pitch and onset within 50 ms.

## Results

| Step | Time | Notes found | P | R | F1 |
|---|---|---|---|---|---|
| Basic Pitch on clean piano (first run, includes model load) | 8.3 s | 59 | 0.51 | 1.00 | 0.67 |
| Basic Pitch on full mix (warm) | 1.0 s | 94 | 0.32 | 1.00 | 0.48 |
| Demucs model load (181 MB download + init) | 11.9 s | | | | |
| Demucs separation of mix | 7.5 s (0.37× realtime) | | | | |
| Basic Pitch on "other" stem | 0.5 s | 66 | 0.45 | 1.00 | 0.63 |

Stems play back in the page (vocals, drums, bass, other), so a play-along backing track with any stem muted is available right after separation.

## Implications

- **Feasible on web.** A 3-minute song would take about 70 s to separate plus a few seconds to transcribe, after a one-time 181 MB model download (cache it).
- **Separation helps:** precision on the mix went from 0.32 to 0.45 with the other stem; recall stays 1.00.
- **Precision is the weak point:** extra notes are mostly overtones and re-triggers. The arranger must clean up: drop notes an octave or a twelfth above a sounding note, merge short re-onsets, quantize to the beat grid, keep the melody line for beginner level.
- 4-stem htdemucs has no piano stem; piano lands in "other" with guitars/synths. A 6-stem model (htdemucs_6s, has piano) is worth testing.
- Synthetic audio is easier than real recordings in some ways (clean onsets) and harder in others (strong overtones). Real-recording numbers are still needed.

## Arranger prototype (bean piano-qjyy, 2026-10-16)

`core/src/arrange.rs`, measured by `core/tests/arrange_fixtures.rs` on the Basic Pitch output captured from the runs above (`core/tests/fixtures/`).

Steps: `clean` drops notes < 60 ms and notes an octave, twelfth or double octave above a louder note that is sounding (amp < 0.8× fundamental); `melody` drops notes that start under a held higher note, then keeps the highest note per onset cluster (60 ms); `arrange` builds level variants.

| Input | Raw F1 | After clean | Melody F1 (P / R) |
|---|---|---|---|
| piano | 0.67 | 1.00 | **1.00** (1.00 / 1.00) |
| mix | 0.48 | 0.62 | **1.00** (1.00 / 1.00) |
| other stem | 0.62 | 0.88 | **0.98** (0.97 / 1.00) |

Level variants (all three inputs):

- **Beginner:** RH melody transposed to C, folded into C4–G4, snapped to C major, one note per beat. Output starts E E F G G F E D as expected.
- **Intermediate:** melody on a half-beat grid + one LH root per bar in C3–B3 (from the lowest sounding note, else the bar's lowest melody note). Mix gives C/G alternation matching the rendered bass.
- **Advanced:** all cleaned notes on a quarter-beat grid, split at middle C.

Caveat: thresholds were tuned on synthetic audio from one melody; numbers will drop on real recordings. Tempo is given (100 bpm), not detected.

## Model benchmark (2026-10-16)

Harness: `tools/spikes/model-bench/bench.py` (Python 3.11 venv, CPU, Windows 11); scoring: `cargo run --example score_notes` in `core/` (same clean + melody steps as the arranger, melody F1, onset ±50 ms). Stems from Demucs `htdemucs_6s` (has piano and guitar stems). New input `nopiano.wav`: sung-like voice (vibrato) carries the melody over plucked guitar chords, bass and drums.

Melody F1 after cleanup + melody step:

| Model | piano | mix | mix→piano stem | mix→other | nopiano | nopiano→vocals | nopiano→other | Time / 20 s |
|---|---|---|---|---|---|---|---|---|
| Basic Pitch 0.4 (Py, ONNX) | **1.00** | **1.00** | 0.98 | 0.80 | 0.48 | 0.45 | 0.60 | ~1 s |
| pYIN (librosa, monophonic) | 0.80 | 0.32 | 0.80 | 0.31 | 0.39 | **0.73** | **0.77** | 3–5 s |
| ByteDance piano_transcription | 0.00* | 0.33 | 0.07* | 0.06 | 0.29 | 0.23 | 0.52 | 13–26 s |
| MuScriptor small (CC BY-NC) | 0.72 | 0.72 | 0.73 | 0.00† | 0.31 | 0.00† | 0.21 | 8–96 s |
| pop2piano | not run: needs `essentia`, no Windows build | | | | | | | |
| Transkun | not run: `ncls` dependency fails to build on Windows | | | | | | | |

\* ByteDance reports the synthetic tone's overtones (octave, twelfth) as notes louder than the fundamental, so cleanup keeps them and the skyline picks them. Our additive "piano" is not realistic; this test is unfair to piano-trained models. Real recordings needed (bean piano-hces).
† MuScriptor returned no notes on these stems; not investigated.

Takeaways:

- **Basic Pitch stays the default** for piano content: best here, small, Apache-2.0, already runs in the browser.
- **No-piano songs:** melody comes best from the Demucs **vocals stem + pYIN** (0.73), or the lead instrument stem + pYIN (0.77). Pipeline: separate → vocals to pYIN for RH melody → bass/other for chords and roots → arranger. pYIN-style tracking is cheap enough to port to Rust/wasm.
- MuScriptor is not better on this set and cannot ship (non-commercial weights).
- pop2piano and Transkun need Linux; test later in WSL or CI.

## Real-song test (2026-10-16)

A user-owned commercial pop recording (vocals, guitar, bass, drums, strings; little piano) was run end to end, locally only: no audio, stems, notes or MIDI were committed. Pipeline: Demucs `htdemucs_6s` → Basic Pitch / pYIN / ByteDance / MuScriptor small on stems or full mix → core arranger (beginner, intermediate, advanced) → MIDI, compared by ear on a local page. GPU (RTX 4070 SUPER, CUDA PyTorch): ByteDance ~45 s, MuScriptor ~3 min on the full mix, ~25 s on the vocal stem.

Findings:

- **Results are not good enough yet.** Arrangements are recognizable in places but not musical or reliably playable.
- **Bug found and fixed:** intermediate/advanced right hand took bass notes in melody gaps (down to MIDI 27) and kept overtones up to MIDI 101. Melody now comes only from notes ≥ middle C; RH folds to ≤ C6 (intermediate) / ≤ C7 (advanced). Regression tests added.
- **Best by ear: `mix-muscriptor`** (MuScriptor small on the full mix, not on a stem), judged by the user across all 8 sources × 3 levels. Cleanest multi-instrument note output, but its weights are CC BY-NC, so it stays a reference unless the license changes or a similar open model appears.
- The deterministic arranger is too blunt for real songs. Level variants probably need an **LLM pass** that reads the transcribed notes (melody, bass, chords, structure) and writes beginner / intermediate / advanced arrangements in our notation, with the core validating range, playability and timing. Rules stay as guardrails; the LLM does musical choices (simplify rhythm, pick chord voicings, keep the hook).
- **No fingering yet.** Arrangements carry no finger numbers. Beginner can use a fixed five-finger map (C=1 … G=5); intermediate needs position rules plus marked shifts; **advanced is where it matters** (thumb-under, chords, leaps) and needs a cost-based fingering algorithm (dynamic programming over hand effort, e.g. Parncutt-style rules) or the LLM pass, with the core checking that fingerings are physically playable.
- The piano stem was nearly empty (32 notes): for songs without piano, melody must come from the vocal stem.

Still to check: pop2piano and Transkun (need Linux), ByteDance on real piano recordings, larger MuScriptor sizes.
