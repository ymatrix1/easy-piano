# Song import spike

Checked: 2026-10-16. Bean: piano-sctg. Decision: [D11](../DECISIONS.md). Code: `tools/spikes/song-import/` (Vite page, `npm install && npm run dev`, open http://localhost:5174 in Chrome).

## Question

Can the browser split a song into stems and transcribe the piano part fast enough for a "My songs" import (D11)?

## Setup

- Chrome on Windows 11, WebGPU available, page cross-origin isolated (COOP `same-origin`, COEP `credentialless`).
- Transcription: `@spotify/basic-pitch` 1.0.1 (Apache-2.0, TF.js), thresholds onset 0.5 / frame 0.3 / min length 5 frames.
- Separation: `demucs-web` 1.0.2 (MIT) on `onnxruntime-web` 1.30.0 (MIT), model `htdemucs_embedded.onnx` (4 stems: vocals, drums, bass, other).
- Test audio: synthetic, generated by `make_test_audio.py`: own rendering of Ode to Joy (PD), 30 notes, 20.2 s, additive "piano" tone with overtones; `mix.wav` adds sine bass and noise drums. Scoring: note F1, same pitch and onset within 50 ms.

## Results

| Step | Time | Notes found | P | R | F1 |
|---|---|---|---|---|---|
| Basic Pitch on clean piano (first run, includes model load) | 8.3 s | 59 | 0.51 | 1.00 | 0.67 |
| Basic Pitch on full mix (warm) | 1.0 s | 94 | 0.32 | 1.00 | 0.48 |
| Demucs model load (181 MB download + init) | 11.9 s | | | | |
| Demucs separation of mix | 7.5 s (0.37× realtime) | | | | |
| Basic Pitch on "other" stem | 0.5 s | 66 | 0.45 | 1.00 | 0.63 |

Stems play back in the page (vocals, drums, bass, other), so a play-along backing track with any stem muted is available right after separation.

## Implications

- **Feasible on web.** A 3-minute song would take about 70 s to separate plus a few seconds to transcribe, after a one-time 181 MB model download (cache it).
- **Separation helps:** precision on the mix went from 0.32 to 0.45 with the other stem; recall stays 1.00.
- **Precision is the weak point:** extra notes are mostly overtones and re-triggers. The arranger must clean up: drop notes an octave or a twelfth above a sounding note, merge short re-onsets, quantize to the beat grid, keep the melody line for beginner level.
- 4-stem htdemucs has no piano stem; piano lands in "other" with guitars/synths. A 6-stem model (htdemucs_6s, has piano) is worth testing.
- Synthetic audio is easier than real recordings in some ways (clean onsets) and harder in others (strong overtones). Real-recording numbers are still needed.

## Arranger prototype (bean piano-qjyy, 2026-10-16)

`core/src/arrange.rs`, measured by `core/tests/arrange_fixtures.rs` on the Basic Pitch output captured from the runs above (`core/tests/fixtures/`).

Steps: `clean` drops notes < 60 ms and notes an octave, twelfth or double octave above a louder note that is sounding (amp < 0.8× fundamental); `melody` drops notes that start under a held higher note, then keeps the highest note per onset cluster (60 ms); `arrange` builds level variants.

| Input | Raw F1 | After clean | Melody F1 (P / R) |
|---|---|---|---|
| piano | 0.67 | 1.00 | **1.00** (1.00 / 1.00) |
| mix | 0.48 | 0.62 | **1.00** (1.00 / 1.00) |
| other stem | 0.62 | 0.88 | **0.98** (0.97 / 1.00) |

Level variants (all three inputs):

- **Beginner:** RH melody transposed to C, folded into C4–G4, snapped to C major, one note per beat. Output starts E E F G G F E D as expected.
- **Intermediate:** melody on a half-beat grid + one LH root per bar in C3–B3 (from the lowest sounding note, else the bar's lowest melody note). Mix gives C/G alternation matching the rendered bass.
- **Advanced:** all cleaned notes on a quarter-beat grid, split at middle C.

Caveat: thresholds were tuned on synthetic audio from one melody; numbers will drop on real recordings. Tempo is given (100 bpm), not detected.
